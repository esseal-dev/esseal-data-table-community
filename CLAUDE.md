## Architecture

This is a **zero-dependency React component library** published as `esseal-data-table` on npm. It ships as a single component (`EssealDataTable`) with accompanying CSS.

### Entry points
- `src/index.ts` — re-exports the component and all public TypeScript types
- `src/EssealDataTable.tsx` — entire implementation (component + helpers + types, all in one file)
- `src/EssealDataTable.css` — all styles using CSS custom properties prefixed `--dg-*`

### Build output (`dist/`)
- `esseal-data-table.js` — ESM build
- `esseal-data-table.umd.cjs` — UMD build
- `esseal-data-table.css` — extracted CSS (consumers must import `esseal-data-table/style.css`)
- `index.d.ts` — rolled-up type declarations (generated by `vite-plugin-dts`)

React and react-dom are **peer dependencies** and externalized from the bundle.

### Component internals (`EssealDataTable.tsx`)

The file is organized in this order:
1. **Exported types** — `GridColDef`, `GridAction`, `SortModel`, `FilterModel`, `TableState`, `DataGridProps`
2. **Internal types** — `GroupNode`, `RowNode` (tree nodes for grouping)
3. **Helper components** — `ActionCell` (inline action buttons + overflow dropdown)
4. **Helper functions** — `groupRows` (recursive tree builder), `flattenTree` (collapses groups), `filterRows`, `sortRows`
5. **Main component** — `EssealDataTable`

### Data pipeline inside the component
Rows flow through: `filterRows` → `sortRows` → `groupRows` → `flattenTree` → pagination slice → virtualization window.

Virtualization is scroll-position based (no library): `startIndex`/`endIndex` computed from `scrollTop` and fixed `rowHeight`, with a 4-row buffer.

### Column ordering
Columns are re-sorted on every render into `[pinnedLeft, unpinned, pinnedRight]`. The `__checkbox` synthetic column is always injected at the start of `pinnedLeft`; `__actions` is always injected at the end of `pinnedRight`.

### State persistence
All interactive state (`page`, `sortModel`, `filterModel`, `expandedGroups`, `columnVisibility`, `pinnedColumns`) is surfaced via the `onStateChange` callback and can be seeded back via `initialState`. The first render is skipped intentionally (`isFirstRender` ref) to avoid firing `onStateChange` on mount.

### CSS conventions
All class names use the `.dg-` prefix. Theming is done entirely via the CSS variables in `:root` at the top of `EssealDataTable.css`. Sticky pinning uses `.pinned-left` / `.pinned-right` utility classes applied to both header cells and data cells.
